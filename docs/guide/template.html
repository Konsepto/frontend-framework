Yleiskuva

Sivuston ulkoasu syntyy kolmesta kerroksesta. Figma määrittelee arvot (värit, koot, välit), front-end-framework tarjoaa valmiit komponentit, ja teema yhdistää ne sivustoksi.

Figma: Protosite Design SystemDesign-tokenit

Muuttujat (värit, typografia, välit, layout) ja suunnittelun komponentit.

themes/front-end-frameworkFramework

CSS-komponentit (core/css, theme-default/css) ja JavaScript-moduulit (core/js/modules). Yhteinen kaikille sivustoille.

themes/protosite + protosite-childTeemat

Parent-teema sisältää WordPress-pohjan. Child-teema on lohkoteema: siinä ovat Protosite-sivuston tokenit, sivupohjat, omat lohkot, tyylit ja JavaScript.

Tyylit ovat natiivia CSS:ää (ei LESSiä). Lightning CSS niputtaa tiedostot yhdeksi css/imports.css-tiedostoksi, muuntaa @custom-media-breakpointit ja sisäkkäisen CSS:n selaimille sopivaksi ja minifioi tuloksen. Frameworkin vanha LESS-versio on edelleen tallessa sivustoille, jotka käyttävät sitä.

Figmasta koodiin

Figma-tiedosto Protosite Design System on suunnittelun ja design-tokenien lähde. Arvot kulkevat koodiin neljän vaiheen kautta:

Figman muuttujatVariables, WEB code syntax

Suunnittelija muuttaa arvon Figmassa.

tokens.jsondesign-tokens/tokens.json

Vienti Figma MCP:n kautta. Commitoitava, tarkasteltava diff.

theme.jsonnpm run tokens

WordPress tekee arvoista CSS-muuttujat --wp--preset--* ja --wp--custom--*.

styles/tokens.cssgeneroitu

Breakpointit ja frameworkin --ff-*-muuttujat theme.jsonin arvoista.

Mitä Figmasta tulee

Koodiin siirtyvät automaattisesti Figman muuttujat (Variables). Komponentit ja näkymät ovat suunnittelun malleja: niitä ei generoida koodiksi, vaan vastaava ulkoasu tehdään CSS:llä.

Semanttiset väritcolor/text/primary, color/button/bg/hoverAutomaattisesti--wp--custom--color--… → --ff-color-…

Muuttujan WEB code syntax Figmassa on sopimus koodin kanssa: se kertoo, mihin theme.jsonin kohtaan arvo kirjoitetaan.

Code syntax Figmassatheme.json
var(--wp--preset--color--X)settings.color.palette, slug X
var(--wp--preset--font-size--X)settings.typography.fontSizes. Desktop-moodi on maksimi ja Mobile-moodi minimi; koko skaalautuu välillä 360–1276 px.
var(--wp--preset--font-family--X)settings.typography.fontFamilies
var(--wp--preset--spacing--X)settings.spacing.spacingSizes
var(--wp--custom--a--b)settings.custom.a.b
Säännöt uusille muuttujille
  • Anna jokaiselle muuttujalle code syntax yllä olevassa muodossa, muuten build pysähtyy virheeseen Unsupported code syntax.
  • Aliakset säilyvät: color/button/bg/hover → var(--wp--custom--gray--40). Muuta siis primitiiviä, jos sama sävy halutaan kaikkialle.
  • Älä nimeä tokeneita small, medium, large, x-large tai 20–80: ne korvaisivat WordPressin oletuskoot, joita tallennettu sisältö käyttää.
  • Palettivärien slugit color-1 … color-8 ovat sisällössä käytössä; älä nimeä niitä uudelleen.
  • Vältä kirjainta heti numeron jälkeen (2xl): WordPress muuttaa sen muotoon 2-xl.

Päivitys vaihe vaiheelta

  1. Muuta arvo Figmassa. Muuta olemassa olevaa muuttujaa tai lisää uusi (code syntax mukaan).
  2. Vie tokenit. Pyydä Claude Codelta: "export Figma tokens to design-tokens/tokens.json". Se ajaa design-tokens/figma-export.js-skriptin Figma MCP:n kautta ja tallentaa tuloksen. Tarkista diff git diff design-tokens/tokens.json.
  3. Generoi theme.json ja tokens.css. 
    cd wp-content/themes/protosite-child
npm run tokens         # tokens.json -> theme.json -> styles/tokens.css
npm run tokens-check   # varmistaa, että generoidut tiedostot ovat ajan tasalla
  4. Rakenna CSS, jos tarpeen. Värit ja fontit ovat WordPressin CSS-muuttujia, joten ne päivittyvät ilman buildia. Fonttikoon, breakpointin tai muun tokens.css:ään vaikuttavan muutoksen jälkeen aja npm run build.
  5. Nosta versio. Kun css/imports.css muuttuu, kasvata $version-arvoa tiedostossa functions.php (rivi 12), jotta selaimet hakevat uuden tyylitiedoston.

Sivustolta Figmaan

Jos tokenin arvoa muutetaan sivuston puolella (theme.json tai Site Editorin tyylit), muutoksen voi viedä takaisin Figmaan. Skripti vertaa nykyisiä arvoja viimeksi generoituun tilaan (design-tokens/theme-tokens.snapshot.json) ja kirjoittaa Figma-skriptin.

npm run tokens:to-figma                    # theme.jsonin muutokset
npm run tokens:to-figma -- --site-editor   # myös Site Editorissa tallennetut tyylit
  1. Skripti listaa muutokset ja kirjoittaa design-tokens/figma-import.generated.js:n. Jos sama token on muuttunut myös Figmassa, se näytetään ristiriitana eikä sitä viedä.
  2. Aja skripti Figma MCP:n kautta design system -tiedostoa vastaan (pyydä Claude Codelta). Se on ensin kuivaharjoitus (DRY_RUN = true) ja kertoo, mitä muuttuisi.
  3. Kun muutokset näyttävät oikeilta, aja se uudelleen DRY_RUN = false, vie tokenit Figmasta uudelleen ja aja npm run tokens. Silloin Figma, theme.json ja snapshot ovat taas samassa tilassa.

CSS:n aloituspiste

Protosite-pohjan tyylit ovat parent-teemassa: protosite/styles/base.css tuo frameworkin käytetyt komponentit frameworkin järjestyksessä ja sivuston tyylit (styles/site/*.css). Jokainen teema rakentaa oman css/imports.css:nsä: ensin frameworkin asetukset, sitten oman sivuston tokenit (jotka korvaavat oletukset), sitten base.css ja lopuksi mahdolliset omat lisäykset.

/* protosite-child/styles/main.css */
@import "../../front-end-framework/theme-default/css/settings.css";
@import "tokens.css";
@import "../../protosite/styles/base.css";

/* geo-seo-ai-tool/styles/main.css: omat lisäykset base.css:n jälkeen */
@import "../../front-end-framework/theme-default/css/settings.css";
@import "tokens.css";
@import "figma-variables.css";
@import "../../protosite/styles/base.css";
@import "site/geo.css";

Parent-teema käyttää samaa rakennetta Protosite Design Systemin oletustokeneilla, joten se näyttää yksinäänkin Protosite-sivustolta. Uudessa, frameworkia suoraan käyttävässä sivustossa voi aloittaa koko frameworkilla ja karsia myöhemmin:

@import "../../front-end-framework/theme-default/css/framework.css";
@import "settings.css";   /* omat --ff-* arvot ja @custom-media */
@import "site.css";
Järjestys ratkaisee

Core-tiedostot tulevat ennen teematiedostoja, ja komponenttien keskinäinen järjestys noudattaa frameworkin framework.css:ää. Kun lisäät komponentin, lisää se parent-teeman styles/base.css:ään samaan kohtaan kuin framework.css:ssä.

Build

npm run build    # minifioitu css/imports.css (epäonnistuu CSS-virheeseen)
npm run dev      # Browsersync + uudelleenrakennus, kun styles/ tai frameworkin CSS muuttuu
npm run check-css  # varoittaa :is()-listoista, jotka muuttaisivat spesifisyyttä

Parent-teemassa (protosite) vastaavat komennot ovat npm run build, npm run dev (build.mjs) ja npm run check-css. Lapsiteeman npm run dev seuraa myös parentin styles/-kansiota.

JavaScript

Frameworkin JavaScript on ES-moduuleja ilman jQuerya. Parent-teema rekisteröi ne import mapiin, ja sen js/main.js käyttää niitä. Lapsiteema voi korvata tiedoston omalla js/main.js:llä.

// protosite/inc/features.php
$frameworkModules = get_template_directory_uri() . $frontendFrameworkPath . '/core/js/modules';
wp_register_script_module('@front-end-framework/animate', $frameworkModules . '/animate.js', [], $version);
wp_register_script_module('@front-end-framework/drawer', $frameworkModules . '/drawer.js', ['@front-end-framework/animate'], $version);
wp_enqueue_script_module('protosite/main', get_theme_file_uri('js/main.js'),
	['@front-end-framework/drawer', /* … */], $version);
// js/main.js
import { drawer } from '@front-end-framework/drawer';
import { navigationMenu } from '@front-end-framework/navigation-menu';
import { accessibleLinks } from '@front-end-framework/accessible-links';

accessibleLinks(document.querySelectorAll('a:not([role="button"])'));
drawer(document.querySelector('#block-search-form'), { group: 'header' });

JavaScriptille ei tarvita buildia.

Uuden komponentin lisääminen frameworkiin

  1. Lisää rakenne tiedostoon core/css/nimi.css ja ulkoasu tiedostoon theme-default/css/nimi.css. Käytä arvoissa --ff-*-muuttujia ja breakpointeissa @media (--small).
  2. Jos tarvitset uuden asetuksen, lisää se oletusarvoineen settings.css:ään.
  3. Lisää @import framework.css:ään oikeaan kohtaan ja sivuston main.css:ään, jos sivusto käyttää komponenttia.
  4. Dokumentoi luokat frameworkin README:hen ja tähän oppaaseen.
Muista ennen committia
  • Älä sisennä sääntöjä sellaisen valitsinlistan alle, jonka valitsimilla on eri spesifisyys: sisäkkäisyys kääntyy :is():ksi, joka saa listan korkeimman spesifisyyden. npm run check-css löytää nämä.
  • Säilytä sääntöjen järjestys, kun siirrät tai yhdistät sääntöjä, ja vertaa tulosta selaimessa edelliseen buildiin.
  • Nosta $version tiedostossa functions.php, kun css/imports.css muuttuu.
  • theme.jsonin global-styles latautuu CSS:n jälkeen: saman spesifisyyden säännöt theme.jsonissa voittavat.

Lohkoteema ja sisältö

Protosite on lohkoteema: sivupohjat ja osat näkyvät ja ovat muokattavissa Site Editorissa (Ulkoasu → Editori). Sivupohjat ja teeman lohkot ovat parent-teemassa protosite, joten kaikki lapsiteemat (protosite-child, geo-seo-ai-tool) perivät ne. Lapsiteema korvaa pohjan tai osan lisäämällä samannimisen tiedoston omaan templates/- tai parts/-kansioonsa. Sisältösivut, listaukset ja kentät tehdään WordPressin omilla lohkoilla ja ACF:llä. Toolsetia ei enää käytetä.

Site Editorissa tehdyt muutokset tallentuvat tietokantaan

Kun pohjaa tai osaa muokataan Site Editorissa, muutos ei mene teeman tiedostoihin, vaan tietokantaan ja ohittaa tiedoston. Pysyvät muutokset kannattaa tehdä tiedostoihin (templates/, parts/) ja commitoida. Site Editorin muutokset saa palautettua tiedoston versioon pohjan valikosta (Palauta).

Sivuston HTML on sama kuin klassisessa teemassa, koska tyylit ja skriptit perustuvat siihen. Siksi pohjissa käytetään kääreinä protosite/element-lohkoa: se tuottaa täsmälleen annetun tagin, id:n ja luokat (esim. <div id="zone-header" class="zone">). Lohko pitää id:n myös editorissa, joten sivuston tyylit näkyvät Site Editorissa oikein.

Listaukset ja suodattimet

Artikkelilistat tehdään WordPressin Query Loop -lohkolla. Sivuston tiiserityyli tulee, kun Post Template -lohkolle annetaan luokka listing listing-teasers ja kohteiden luokat Lisäasetukset → Item classes -kenttään: article-teaser teaser teaser-{type} ({type} = sisältötyyppi).

<!-- wp:query {"queryId":1,"query":{"perPage":6,"postType":"post","order":"desc","orderBy":"date","inherit":false}} -->
<div class="wp-block-query">
  <!-- wp:protosite/query-filter {"controls":[{"taxonomy":"category","display":"radios","label":"Kategoriat","allLabel":"Kaikki","showCount":true}],"submitLabel":"Haku"} /-->

  <!-- wp:post-template {"className":"listing listing-teasers","itemClass":"article-teaser teaser teaser-{type}"} -->
    <!-- wp:post-featured-image {"isLink":true,"sizeSlug":"full"} /-->
    <!-- wp:post-title {"level":3,"isLink":true} /-->
    <!-- wp:protosite/post-meta {"showType":true} /-->
    <!-- wp:post-excerpt {"excerptLength":12} /-->
    <!-- wp:read-more {"content":"Lue lisää","className":"link-more"} /-->
  <!-- /wp:post-template -->

  <!-- wp:query-pagination … /-->
</div>
<!-- /wp:query -->

Suodatinlomake. protosite/query-filter lisätään Query Loop -lohkon sisään. Suodattimet asetetaan lohkon sivupaneelissa JSON-listana:

AsetusArvot
taxonomyTaksonomian nimi, esim. category, post_tag
displayradios, checkboxes tai select
label, allLabelOtsikko ja "kaikki"-vaihtoehdon teksti
showCount, hideEmptyNäytä kohteiden määrä; piilota tyhjät termit (oletus kyllä)
{"search": true, "label": "…"}Tekstihaku otsikoista

Lisäksi Submit button on lähetysnapin teksti ja Post types listaa useita sisältötyyppejä (Query Loop -lohkoon voi valita vain yhden). Termit järjestetään termien omaan järjestykseen. Suodattimet näkyvät osoitteessa muodossa ?filter-category=uutiset, ja sivutus muodossa ?query-1-page=2.

protosite-childissa arkistoissa ja haussa näytetään kaksi kohdetta sivulla, ja arkistot ovat uusimmasta vanhimpaan (childin functions.php, pre_get_posts). Muut sivustot käyttävät WordPressin lukuasetuksia.

Kentät ja taksonomiat (ACF)

Lisäkentät ja omat taksonomiat ovat Advanced Custom Fieldsissä. Määrittelyt tallentuvat automaattisesti teeman acf-json/-kansioon, joten ne kulkevat versionhallinnassa ja palvelimille teeman mukana. Kun kenttiä muutetaan ACF:n hallinnassa, commitoi muuttuneet JSON-tiedostot.

Arvot luetaan ACF:n funktioilla, esim. get_field('event_date'). Toolsetin tiedot siirrettiin skriptillä tools/migrate-from-toolset.php (wp eval-file … [dry-run]), ja Toolsetin jäänteet on sen jälkeen poistettu tietokannasta. Skripti on mukana muiden Toolset-sivustojen siirtoa varten.

Lomakkeet (Fluent Forms)

Lomakkeet tehdään Fluent Formsilla (Contact Form 7 on poistettu käytöstä). Lomake lisätään sivulle Fluent Forms -lohkolla. Sivuston lomaketyyli tulee automaattisesti (styles/site/plugins.css):

  • Kenttien otsikot ovat lihavoituina kenttien yläpuolella, ja kentät ovat 400 px leveitä (mobiilissa koko leveys).
  • Pakollisuustähteä ei näytetä: kirjoita "(pakollinen)" otsikkoon.
  • Lähetä-nappi on harmaa, kunnes ehtojen valintaruutu on valittu.

Valitse lohkon tyyliksi Inherit theme style ja jätä lohkon marginaalit nollaan. Käytä ehtojen tekstin linkeissä suhteellisia osoitteita (/privacy-policy), jotta ne toimivat kaikissa ympäristöissä.

Komponentit

Esikatselut käyttävät frameworkin oikeaa CSS:ää oletusasetuksilla (framework.css). Protosite-sivustolla samat komponentit saavat arvonsa Figman tokeneista, joten pyöristykset ja koot voivat poiketa hieman. Vaihda esikatselun leveydeksi 375 px nähdäksesi pienen näytön (--small) tyylit.

Asetukset

Frameworkin asetukset ovat tiedostossa theme-default/css/settings.css. Protosite-childissa styles/tokens.css korvaa ne theme.jsonin arvoilla (esim. --ff-color-text-primary: var(--wp--custom--color--text--primary)).

Breakpointit

Käyttö: @media (--small) { … }. Protosite-childissa --small on alle 748 px ja --large vähintään 924 px (Figman breakpoint/small ja breakpoint/large).
